## Behavior and API constraints for migration

### S1/S4 — checkbox labels, group disabling and identity

`controller_session.rs:41-55` wraps selections in a disabled fieldset from prepared `view.editable`; each row separately applies `!row.enabled`, `row.selected`, its prepared device label, and disconnected suffix. Preserve both layers of disabling and dispatch exactly one `Action::Select { device, selected: event.checked() }` on change. `virtual_config.rs:32` also has group disabling, and axis checkboxes use `!editable`, `config.axes.contains(&axis)`, the axis-specific accessible name and `Action::Axis`.

`Checkbox` currently renders its own outer `<label>` (`src/components/checkbox.rs:72`), accepts `id`/checked/disabled/change, and accepts neither label children nor `aria_label`. Do not put it inside the consumers' existing `<label>` elements: that produces nested labels. The minimal shared extension is optional label content, which preserves the whole-row click target and dynamic names. Alternatively use stable id plus a separate associated `Label` in a layout wrapper. The disconnected suffix must remain visible and appropriately included in the label. Do not recreate selected/axis policy inside the component.

### S2/S3 — native raw change is a protected behavior

Both raw number fields forward `event.value()` unchanged on **native change**, including invalid text, to app-owned `Action::Buttons`/`Action::Hats`; limits are driver-provided. `controller_events_tests.rs:123-135` sends a `change` event containing `"not-a-number"`, and `:157-164` explicitly expects the untouched value in the app intent. This is evidence that a parsed-commit substitution changes behavior.

`IntegerInput` commits parsed `usize` only on Enter/blur and emits `IntegerInputError` locally; `NumberInput` commits parsed/clamped `f64` on Enter/blur and adds steppers. Neither exposes the native raw `onchange` event. Add only the shared presentation/API needed for native raw-change numeric controls, preferably an unparsed numeric leaf reused by the existing numeric composers. A small explicit native-change mode/prop is an alternative, provided it does not run the parsed/clamped commit path too. Preserve the raw app-validation boundary, exact limits, slot identity, disabled flags, readable labels, and current native commit timing. Do not adapt by parsing in the GUI or converting through floats.

### S5 — selectable row is a common control, row content remains domain-owned

The raw device button has `type="button"`, `aria-pressed`, click-to-inspect, native Enter/Space activation and focus-visible treatment. It intentionally does **not** select routing. Keep these in a generic reusable row-control surface, while the domain row retains names, connection badge, hardware-name clamp/title and usage badges. It should be able to carry arbitrary content and explicit selected/pressed state without repainting a normal action button through consumer CSS. Profile/library rows in the sibling audit can use the same primitive where their semantics agree.

The `.if-device-row` CSS explicitly copies profile row appearance (`panel_slot.css:155-160`) and repeats the shared button active 1px/2px press/focus/hover machinery. Centralize those visual states. Do not move the layout-only name/headline/count wrappers (`:171-210`) into an all-knowing device component. Preserve existing selected aria state and independent routing/inspection behavior.

### S6 — display name is already manually reimplementing TextInput

`inspector.rs:15-19` calls `components::behavior().text` directly, then `:43-50` manually renders `initial_value`, `data-if-text-owner`, text-input class names and the returned input callback. This is the exact composition owned by `TextInput`, so a second wrapper is unnecessary. `TextInput` already has `onkeydown`; preserve the app key call and `prevent_default` only when acknowledged (`inspector.rs:29-36`). Give the visible Display name label proper association via `Field`/`Label` and a stable id, or extend `TextInput` with accessible-name forwarding. Keep the DS inset-focus modifier through its supported class channel or a shared focus-variant API.

Remove private border/radius/background/color/padding definitions from `.if-device-inspector__input` (`panel_slot.css:230-235`); these duplicate `assets/components/text-input.css:3-8` exactly today. Keep only width/min-width layout (`:228-229`) in consumer CSS. `.if-device-inspector__field` (`:220-225`) duplicates label/control spacing and type presentation; `Field`/`Label` are existing replacements, with `.if-device-inspector__edit-row` retained for the input-plus-Save arrangement.

The error at `inspector.rs:60-61` is a workflow alert, not necessarily only input validation. Keep generic workflow errors visible; do not blindly move every message into `Field.error` or label it as invalid input. A shared inline-feedback/alert component, if adopted across consumers, should own repeated error type/color while the consumer owns placement. Preserve failed Save draft retention and existing error clearing through the app. Existing event regressions (`device_panel/event_tests.rs:88-174`) cover failed Save, rapid Unicode typing without native value echoes, Enter failure and Escape cancellation. A migration must continue using the stable app text owner and `initial_value`; changing to controlled `value` can regress typing.

### S7 — toast close can use IconButton without changing queue policy

Keep `Interaction::Dismiss` exactly as wired, and retain hover/focus pause plus Escape handling on the toast host. `.if-toast__close` currently owns size, align, border/radius/color/cursor/type, hover/active and focus, duplicating an icon-action primitive. Replace it with `IconButton`; leave only layout (`flex-shrink`) in toast CSS. Accept standard shared small geometry or add a documented compact shared size if the product actually requires 22px. Do not preserve this through private width/height/color/focus overrides on `.if-icon-button`.

The host `div` at `viewport.rs:67-75` is **not** a fake clickable control: it has no onclick. `tabindex=0` allows focus-pause and Escape; warning/error roles are `alert`, info/success inherit the polite stack. Keep it as notification content, not a wrapping button around another button. Preserve chronological order, count coalescing, roles, queue disposal and existing timer policy.
